# multi-model-orchestra v1.1.0

The first release handed work to four CLIs. This one reaches 32 lanes, checks what a lane did instead of
taking its word, and routes by what really answers on your machine. Much of it came from the comments on
the Reddit posts about v1.0.0.

## Highlights

- **32 lanes, one adapter file each.** `mmo-run --list` shows every lane, whether its CLI is installed, and
  how far it has been checked. Run for real by the maintainer: Claude, Codex, Kimi, DeepSeek, OpenCode, Grok,
  Cursor, Antigravity, Copilot, and the `api` lane (any OpenAI-compatible endpoint, no agent CLI needed).
  The rest were written from each CLI's documentation, nine of them checked against the real tool's help,
  and are marked as such.
- **`mmo-check`: the conductor runs the check itself.** It lists files touched outside the brief, existing
  tests that were changed or deleted, changed dependency manifests, and with `--red` it demands that the
  check fails on the base code: a check that passes without the change proves nothing.
- **`mmo-roster`: route by what answers here.** One tiny call per lane, then a lineup per tier that the
  conductor tells you before the first brief. `probe --write` checks from the outside that a lane can write
  files and run commands. A lane at its limit is skipped until the time its own error message names.
- **Ceilings the caller owns.** `--base` (refuse a stale worktree), `-t`, `--idle`, `--loop`, `--max-turns`,
  `--max-cost`. A lane cannot raise its own limits.
- **Cost you can see.** A hook that refuses a sub-agent call with no model named, usage and cost recorded
  where the tool reports them, `mmo-score` for first-try pass rate, cost per passed task, share of work per
  family and escalation advice per task.
- **`advisor` skill and `mmo-advise`.** The other way round: a cheaper model does the task and asks a
  stronger one, from any vendor, for a short verdict at three moments.
- **`mmo-lessons`.** A capped log of lessons about a lane that can only be written with a passing check
  report as proof. Not a memory system, on purpose.
- **`mmo-cloud` (experimental).** Devin, Cursor cloud agents and Copilot agent tasks behind one status
  contract. Written from vendor documentation and tested against fakes only.
- **otomode** no longer drifts to Claude lanes only: it probes every lane at the start, sends each task to
  the first ready lane of its tier, verifies with `mmo-check`, and takes out only the lane that hit a limit.
  A real end-to-end run is described in [otomode.md](../otomode.md).

## Numbers, and what they do not show

- **A/B, third arm.** One sentence ("Use Sonnet subagents for implementation, and name the model explicitly
  on every sub-agent call.") averaged $1.49 over two runs, against $3.21 for plain "use subagents" and $1.88
  for the orchestra skill a week earlier, all at 36/36 hidden tests. On this small, easy task set the single
  sentence captured the whole saving. Two runs per arm, arms run on different days: not a controlled
  comparison. What the skill adds beyond the model choice (other vendors, status gates, worktree-only
  writes, the conductor's own check) was not measured by this test.
- **Lane benchmark, 41 lanes.** Nearly every lane scored full marks on the three small tasks; they differ in
  speed. See [COMPARISON.md](../../bench/results/2026-11-28/COMPARISON.md).
- **Harder tasks did not separate the tiers either.** Three harder tasks and one large one (a 47-file
  application, 59 hidden tests in five groups) were added with grading that resists edited tests. A cheap
  lane, a middle lane and a strong lane each scored 59/59 twice on the large task; one lane scored 57/59
  twice and still reported DONE. The reading: well-specified work passes on cheap lanes, time separates
  lanes more than score does, and a lane's DONE is a claim. Eight runs on one machine.

## Upgrading

```bash
git pull
./install.sh            # replaces nothing that exists: move the old skill folders away first
~/.claude/skills/orchestra/scripts/mmo-roster probe
```

- `mmo-run`'s old calls work unchanged. New exit codes: 9 (wrong base); status words `stalled` and `looping`
  share exit 4 with `timeout`.
- Keys can live in `~/.config/mmo/keys.env`, model ids for lanes without a default in `~/.config/mmo/models`,
  and your own order within a tier in `~/.config/mmo/prefer`.
- otomode: `otomode.py on` now refuses without a session id or without a `Lanes:` line in the plan.

## Known limits

- Most lanes are marked `docs-<version>` or `help-<version>`: nobody has seen them answer. A one-line brief
  and its header line is the most useful report you can send.
- The shell tests were run on Windows (Git Bash) only before this release.
- Usage and cost are recorded only for the Claude lanes and the `api` lane; the other CLIs' known output has
  no such fields. Claude's figure is a list-price number, not what a plan bills.
- The 18 README translations were updated by a model. Crimean Tatar and Uyghur need a native reader most.
- The full list of changes is in the [CHANGELOG](../../CHANGELOG.md).
