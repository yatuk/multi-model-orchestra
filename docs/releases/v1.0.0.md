# multi-model-orchestra v1.0.0

Skills and scripts that let one expensive conductor model hand work to cheaper lanes (Claude Opus, Sonnet and Haiku, GPT through Codex, Kimi, DeepSeek) and check every answer before using it. A single runner gives every lane the same status codes, writes happen only in worktrees, and decisions go through a blind three-model council.

## Highlights

- One runner, `mmo-run`, for Codex, Kimi, DeepSeek and Claude, with hard status codes: ok, failed, timeout, empty, limit, auth and the new `model` (exit 8, the model id was rejected).
- Limit detection reads only the CLI's own error lines, so a brief echoed on stderr no longer causes a wrong `limit` or `failed` status.
- Write lanes run only in linked git worktrees; read-only Kimi and DeepSeek lanes run in throwaway worktrees.
- `mmo-council` asks three model families the same question, read-only, and shuffles the answers before you judge them.
- `otomode` runs a task list while you are away: one round of questions, then every prompt is denied and logged. The hook now judges only commands that actually run, and it has a `log` command, a cleanup list for blocked housekeeping, base-branch and quick-check rules, and smoke tests of every model id before the run.
- A benchmark and an A/B test ship with their raw results, graded without a model in the loop.
- README in 19 languages, including Crimean Tatar in Latin script, plus GitHub issue and PR templates and a light CI.

## Numbers

A/B test, orchestra skill against the prompt "Use subagents for implementation." Main model `claude-fable-5-2`, four small Python tasks, 36 hidden tests, 2 runs per arm:

| Arm | Hidden tests | Mean cost | Mean wall time |
|---|---|---|---|
| Plain "use subagents" | 36/36 in both runs | $3.21 | 3.5 min |
| Orchestra skill | 36/36 in both runs | $1.88 | 3.2 min |

- All four runs passed all 36 hidden tests, so the tasks do not separate the arms on quality.
- The skill arm cost about 40% less. The saving comes from sub-agents running on Sonnet instead of inheriting Fable.
- No speed gain.
- A one-line prompt such as "use Sonnet subagents" was not tested, and it may capture most of the saving.
- Cost is the CLI's list-price figure, a proxy for plan usage, not a bill.

One otomode run over 5 hours: 13 tasks done, weekly limit usage went from 25% to 31%. This was one run, not a benchmark.

## Install

Needs bash, git, `timeout` and Python 3. Each lane needs its own CLI, signed in: `codex` for GPT, `kimi` for Kimi and DeepSeek.

```bash
git clone https://github.com/yatuk/multi-model-orchestra
cd multi-model-orchestra
./install.sh --link          # into ~/.claude/skills; --dir PATH for a project
~/.claude/skills/orchestra/scripts/mmo-preflight
```

For otomode, run `python ~/.claude/skills/otomode/scripts/otomode.py install` once to register its hook.

## Known limits

- On Windows, use Git Bash.
- Kimi Code has no read-only sandbox and edits files in print mode even when asked not to, so read-only Kimi and DeepSeek lanes run in throwaway worktrees.
- The otomode hook is a guard rail, not a sandbox.
- Model ids differ per plan and change over time. Smoke-test the ids your plan serves before relying on them.
- The benchmark and A/B test are small: one or two runs per cell, easy tasks.
